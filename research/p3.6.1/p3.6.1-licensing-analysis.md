# Phase P3.6.1: Licensing & Distribution Analysis

## 1. Executive Summary

This report analyzes the legal, intellectual property, and distribution considerations surrounding Google's `language_server` binary, distinguishing between unauthorized redistribution and legitimate dynamic retrieval architectures.

### 2.1 The Proprietary Status of `language_server`
- The `language_server` binary is compiled from Google's internal proprietary monorepo (`google3`), specifically:
  `//depot/branches/antigravity_web_release_branch/1011819993.1/google3`
- It is governed by **Google Terms of Service** and specific Antigravity service terms.
- Google has not published `language_server` under an open-source license (such as Apache 2.0 or MIT).
- **Redistribution Barrier**: Embedding the 188 MB proprietary binary inside a publicly distributed APK (e.g., hosted on GitHub Releases, F-Droid, or Google Play) would constitute unauthorized distribution of Google proprietary binaries, exposing the project to DMCA takedown notices and developer account suspension.

---

### 2.2 The Legitimate Dynamic Retrieval Architecture

To achieve a standalone Android port without infringing Google's distribution rights, the project can mirror the exact architecture used by Google's own desktop application:

#### How Google's Desktop Application Handles Linux Binaries:
As revealed by our audit of `app.asar/out/main/index.js`, the Windows Antigravity desktop application **does not bundle the Linux binary**:
```javascript
// Excerpt from Antigravity Desktop app.asar
async function resolveServerBinarySource(version, isInsiders) {
    const arch = process.arch === 'arm64' ? 'arm64' : 'x64';
    const artifactDir = await resolveStableArtifactDir(version);
    const url = `${artifactDir}/unsigned/language_server-linux-${arch}`;
    console.log(`[WSL] Downloading server binary from ${url}`);
    const res = await fetch(url);
    return Buffer.from(await res.arrayBuffer());
}
```
When a Windows user switches to a WSL Linux environment, the application downloads the official Linux binary on demand directly from Google's public cloud storage bucket (`storage.googleapis.com/antigravity-public/`).

#### How Community Tools (`AFSlayer/antigravity-server`) Handle Distribution:
The `antigravity-server` repository explicitly states in its documentation:
> *"This project does not redistribute any proprietary Google binaries. All installation scripts fetch official release artifacts directly from Google's public cloud storage."*

---

### 2.3 Proposed Android Distribution Architecture

1. **Clean-Room APK Package**:
   - The distributed Android APK contains **zero proprietary Google binaries**.
   - The APK includes only the open-source Android UI shell, the PRoot native shared library (`libproot.so`), and a minimal stripped Debian rootfs (~150 MB compressed to ~40 MB).
   - APK size remains compact and clean.
2. **On-Demand First-Run Setup**:
   - When the user first launches the application (or selects "Standalone Mode" in Settings), a setup wizard displays:
     > *"Downloading official Antigravity Core from Google Cloud Storage..."*
   - The application fetches `language_server-linux-arm64` directly from:
     `https://storage.googleapis.com/antigravity-public/antigravity-hub/<version>-<execution_id>/unsigned/language_server-linux-arm64`
   - The application computes the SHA-256 hash of the downloaded binary and verifies it against Google's published release metadata before placing it in the PRoot execution directory.
   - The transaction occurs strictly between the user's device and Google's public servers.

---

## 3. Conclusion on Licensing

Bundling Google's 188 MB binary inside an APK is legally impermissible.

However, an **Automated Dynamic Fetching Model** (downloading directly from Google's public distribution bucket on the user's device during setup) is **100% legally sound, preserves copyright compliance, and follows Google's own established desktop WSL architecture**.
