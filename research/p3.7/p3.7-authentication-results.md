# Phase P3.7: Authentication Architecture & Findings

## 1. Authentication Analysis Overview

In Antigravity desktop, authentication provides the identity and access tokens needed to access Google's internal inference backend for original Cascade conversations and original models (Gemini 1.5 Pro, Flash, Claude 3.5 Sonnet, etc.).

During Phase P3.7 on-device execution, the authentication flow was rigorously tested against Google's `language_server-linux-arm64` binary.

---

## 2. Empirical Findings

### 2.1 The `$HOME` Requirement for Token Store
When `language_server` starts up, its Go runtime calls `auth_client.go:177` (`os.UserHomeDir()`).
- On standard Linux, `HOME` is `/root` or `/home/<user>`.
- Under Android's Bionic process execution, `HOME` is unset by default.
- If `HOME` is unset, `language_server` crashes with a nil pointer dereference when accessing its credential store.
- **Resolution**: Setting `"HOME" to "/root"` in PRoot environment provides a valid, persistent token storage directory at `/root/.config/antigravity` (physically stored inside `/data/user/0/dev.agentic.workspace/files/rootfs/root`).

### 2.2 Discovery of `LoginWithBrowser` Deprecation
In P3.5 desktop investigation, `LoginWithBrowser` was presumed to trigger an OAuth URL generation.
When invoked on the unmodified binary (`1.11.0`):
- **Request**: `POST /exa.language_server_pb.LanguageServerService/LoginWithBrowser`
- **Response**: `HTTP 500 Internal Server Error`
- **Error Payload**:
  ```text
  interceptor.go:70: LoginWithBrowser is deprecated and no longer supported
  ```
- **Technical Implication**: Google has deprecated this RPC endpoint in favor of direct OAuth token submission via `Login` or external host-driven authentication.

### 2.3 The `Login` Connect-RPC Endpoint
Inspection of the binary strings and proto definitions confirms the primary active authentication RPC is:
- **Endpoint**: `/exa.language_server_pb.LanguageServerService/Login`
- **Request Schema**:
  ```json
  {
    "authToken": "<google_oauth_token>",
    "email": "<user_email>"
  }
  ```
- Calling `Login` allows injecting an authentic Google Cloud Code / Antigravity OAuth 2.0 access token directly into the language server's memory and disk cache.

### 2.4 Browser-Redirect OAuth URL Detection (`ANTIGRAVITY_OPEN_URL`)
When the backend triggers an OAuth login flow, it outputs an authorization URL to stdout matching the regex:
```
ANTIGRAVITY_OPEN_URL:\s*(https?://\S+)
```
`LocalBackendLifecycleManager` implements live stdout monitoring on `proc.inputStream`. When this pattern appears, it captures the URL and surfaces it to `latestAuthUrl` StateFlow, allowing the Android application to open an `Intent.ACTION_VIEW` or `CustomTabsIntent` directly to Google's authentication page.

### 2.5 Auth Status Evaluation (`GetAuthStatus` & `GetUserStatus`)
Before login:
- `GetAuthStatus` returns empty / unauthenticated descriptor.
- `GetUserStatus` returns:
  ```json
  {
    "userStatus": {
      "cascadeModelConfigData": {
        "errorMessage": "failed to get load code assist response: error getting token source: You are not logged into Antigravity."
      }
    }
  }
  ```
This confirms that the original backend is running genuine Google authentication verification and will not proceed to Cascade inference without a genuine Google account session.
