# Phase P3.7: RPC Integration & Protocol Relay Specification

## 1. Overview

In **Mode B (Standalone In-App Backend)**, the Android application does not connect over WiFi to an external desktop IP. Instead, all communication occurs via loopback IPC (`127.0.0.1:<httpPort>`).

The system uses a unified relay architecture: `LanguageServerGrpcWebHandler` intercepts RPC requests from the Jetski frontend and routes them directly to the local language server through `HubProxyHandler`.

---

## 2. RPC Framing & Protocol Details

### 2.1 Connect-RPC vs gRPC-Web
The Google Antigravity language server natively exposes **Connect-RPC** (over loopback HTTP) and **gRPC** (over TLS on `httpsPort`).
The Jetski single-page application and the native Android Compose UI communicate primarily via Connect-RPC:
- **Wire Format**: JSON or binary Protobuf over standard HTTP/1.1 POST.
- **Protocol Header**: `Connect-Protocol-Version: 1`.
- **CSRF Protection Header**: `x-codeium-csrf-token: <csrfToken>`.
- **Content-Type**: `application/json` or `application/proto`.

### 2.2 Relay Routing in `LanguageServerGrpcWebHandler`
The routing logic inside `LanguageServerGrpcWebHandler` handles both Mode A and Mode B identically through `hubProxyHandler`:

```kotlin
// LanguageServerGrpcWebHandler.kt lines 255-263
BackendMode.ORIGINAL_DESKTOP_HUB, BackendMode.STANDALONE_IN_APP_BACKEND -> {
    if (hubProxyHandler != null) {
        val proxyResult = hubProxyHandler.relayRequest(request)
        if (proxyResult != null) {
            return proxyResult
        }
    }
    // Fallback if hub is not reachable or unconfigured
    Log.w(TAG, "Backend mode $activeBackendMode is selected but Hub is not connected")
    createGrpcWebErrorResponse(
        grpcStatusCode = 14, // UNAVAILABLE
        message = "Original backend selected ($activeBackendMode) but local Hub is not connected"
    )
}
```

## 4. Streaming & Bi-directional Communication

1. **Connect-RPC Server Streaming**:
   When streaming Cascade turn updates or agent output chunks, the Connect-RPC protocol uses standard chunked transfer encoding (`Transfer-Encoding: chunked`) with 5-byte framing prefixes:
   - Byte 0: Flag byte (`0x00` = data frame, `0x02` = end-of-stream trailer frame).
   - Bytes 1-4: 32-bit big-endian payload length.
2. **Relay Framing Preservation**:
   `HubProxyHandler` streams raw HTTP chunks directly from OkHttp's `ResponseBody.byteStream()` to the caller without re-buffering or stripping framing bytes, ensuring real-time token streaming from Cascade to the UI.
