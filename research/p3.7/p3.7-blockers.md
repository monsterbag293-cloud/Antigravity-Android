## 2. Deep Dive: Criterion E (Authentication)

### 2.1 The Deprecation of `LoginWithBrowser`
In older versions of the Google language server (or Codeium lineage), calling `LoginWithBrowser` prompted the local server to spin up a temporary loopback web redirect handler or emit an auth URI.
In binary version `1.11.0` (used in Antigravity), invoking this endpoint returns:
```text
interceptor.go:70: LoginWithBrowser is deprecated and no longer supported
```
This is an intentional upstream architectural change by Google. In the official Antigravity desktop application, authentication is handled via the Electron main process using Chrome WebContents or Google Identity Services, which exchanges an OAuth authorization code with `https://oauth2.googleapis.com/token` and passes the resulting token into the language server via the `Login` RPC:
```json
{
  "authToken": "<google_access_or_refresh_token>",
  "email": "<user_email>"
}
```

### 2.2 Feasibility of Full Android Standalone Auth
To achieve unassisted standalone authentication in Android APK Mode B:
1. The Android app must register an OAuth 2.0 Client ID (Android application type with package name `dev.agentic.workspace` and SHA-1 signing certificate fingerprint) in Google Cloud Console.
2. The user initiates Google Sign-In using Android's Credential Manager or Google Sign-In SDK with the `cloud-platform` / Cloud Code scopes.
3. The retrieved OAuth token is submitted via Connect-RPC `Login` to `127.0.0.1:<httpPort>/exa.language_server_pb.LanguageServerService/Login`.
4. Alternatively, desktop users can export their existing Antigravity session token from `~/.config/antigravity` or scan a pairing QR code.

## 3. Deep Dive: Criterion F (Cascade Execution)

### 3.1 Hard Server-Side Verification
Unlike local LLM runners (e.g. llama.cpp or Ollama), Google's `language_server-linux-arm64` does not contain the LLM weights. It is an intelligent client orchestrator and language engine that proxies semantic queries and agentic tool invocations to Google's internal Cloud Code / Antigravity inference servers.

When `GetUserStatus` or `StreamCascade` is called without an authenticated session, the server-side proxy aborts immediately:
```json
{
  "errorMessage": "failed to get load code assist response: error getting token source: You are not logged into Antigravity."
}
```

### 3.2 Integrity Commitment
Under strict project rules:
- We **do not** fake or mock the authentication response.
- We **do not** substitute the P1.3 Gemini fallback and pretend it is the original backend.
- We report honestly that while the binary runs locally with 100% fidelity inside the APK sandbox (Criteria A-D PASS), genuine Cascade turns (Criterion F) require a valid Google Cloud Code authenticated session (Criterion E).
