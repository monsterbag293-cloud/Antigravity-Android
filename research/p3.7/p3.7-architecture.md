# Phase P3.7: Architecture Specification — Standalone Mode B In-App Backend

## 1. Architectural Overview

Phase P3.7 achieves the milestone of **Mode B: Standalone Original Antigravity on Android**. The architecture enables the unmodified Google language server (`language_server-linux-arm64`) to execute locally on an Android device inside the unprivileged application sandbox of `dev.agentic.workspace`, eliminating the requirement for a paired desktop host, an external server/VPS, or a paid proxy backend.

## 2. Key Subsystems and Interaction

### 2.1 Backend Provisioning Subsystem (`BackendProvisioningManager`)
- **Asset Integrity**: Debian rootfs archive (`rootfs.tar.gz`, 28,144,358 bytes) is staged in the APK `assets/` directory.
- **On-Demand Extraction**: Extracted into application-private storage (`/data/user/0/dev.agentic.workspace/files/rootfs`) using Android's native `/system/bin/tar`.
- **Language Server Acquisition**:
  - Validates pre-staged local candidates (e.g. `/data/local/tmp/proot_test/rootfs/usr/bin/language_server`).
  - Downloads the official release binary from Google Cloud Storage (`https://storage.googleapis.com/antigravity-public/antigravity-hub/2.29.1-5241471524274176/unsigned/language_server-linux-arm64`).
  - Verifies exact size (`188,567,928` bytes) and SHA-256 checksum (`79c885734bd7aa10ce116ad7bd5117ca6e552501d9f412ba42c33cbca8610784`).
  - Sets executable permissions (`chmod 0755`) within the Linux rootfs.

### 2.2 Process Virtualization Subsystem (`LocalBackendLifecycleManager`)
- **Native Packaging**: `libproot.so` (285,336 bytes), `libproot_loader.so` (18,520 bytes), and `libtalloc.so` (44,552 bytes) are packaged in `jniLibs/arm64-v8a/` and extracted to `context.applicationInfo.nativeLibraryDir`.
- **Android W^X Compliance**: Android blocks executing binaries located in writable app storage. Packaging PRoot as an `.so` file inside `nativeLibraryDir` complies fully with Android's W^X policy (`apk_data_file:s0:c...`).
- **Dynamic Port Selection**: Automatically scans for available TCP loopback ports starting from `58888` to prevent `EADDRINUSE` port collision on rapid restart.
- **Process Orchestration**: Spawns `libproot.so` with chroot arguments (`-r`, `-b /proc`, `-b /dev`, `-b /sys`), sets `$HOME=/root`, `$USER=root`, `$PATH=/usr/bin:/bin`, and launches `language_server` with daemon parameters:
  - `--standalone=true`
  - `--persistent_mode=false`
  - `--http_server_port=<port>`
  - `--csrf_token=<token>`
  - `--gemini_dir=/tmp/gemini_app`
  - `--app_data_dir=antigravity`
  - `--disable_telemetry=true`
  - `--headless=false`
  - `--override_ide_name=antigravity`
  - `--subclient_type=hub`
- **Non-blocking Daemon Mode**: Closes `stdin` immediately upon start to trigger Google's daemon mode instead of interactive console authentication.

### 2.3 IPC and Discovery Subsystem
- **Metadata Discovery**: Language server generates a JSON discovery descriptor at `<gemini_dir>/<app_data_dir>/daemon/hub_<port>.json`:
  ```json
  {
    "pid": 28324,
    "httpsPort": 44447,
    "httpPort": 58888,
    "lsVersion": "1.11.0",
    "csrfToken": "ag_sandboxed_..."
  }
  ```
- **Automatic Binding**: `LocalBackendLifecycleManager` polls for file creation (latency ~336 ms), parses dynamic ports and CSRF token, and initializes `RemoteHubConnectionManager`.
- **Health Monitoring**: Periodically reads `/proc/<pid>/status` for RSS memory consumption and polls backend connectivity.
