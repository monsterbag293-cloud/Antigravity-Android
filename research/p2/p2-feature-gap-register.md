# Phase P2: Feature Gap Register & Architecture Debt Inventory

## Overview
This register documents independently discovered functional, architectural, and protocol gaps between the original Google Antigravity desktop application and the current Android port. Each entry provides technical evidence, impact assessment, and the recommended action.

---

### GAP-01: Hub Discovery & Remote Language Server Pairing
- **Feature:** Remote Antigravity Daemon Discovery and Connection.
- **Original Location:** `language_server.exe` (`server.go:3344`), `dist/languageServer.js`, `~/.gemini/antigravity/daemon/hub_<port>.json`.
- **Required Services/RPCs:** Connect-RPC / gRPC-Web transport, `x-codeium-csrf-token` header injection, loopback/LAN HTTPS listener.
- **Current Android Status:** Not Implemented. Android port exclusively targets in-process mock handler on loopback.
- **Missing Functionality:** 
  1. No mechanism for the Android app to discover or enter desktop daemon connection details (IP, port, CSRF token).
  2. No SSL trust bypass for remote local-network IP addresses in Android WebView.
  3. No proxying or direct routing of gRPC-Web requests to a paired desktop instance.
- **Dependencies:** Android network security config (`cleartextTrafficPermitted` or custom `X509TrustManager`), pairing UI settings screen.
- **Priority:** **P0 (Critical)** — Resolves the primary blocker for genuine Antigravity AI execution by allowing pairing with a genuine desktop daemon.
- **Evidence:** `language_server.log: server.go:3344] Wrote hub discovery file: hub_57734.json`; `--subclient_type=hub` flag in `dist/languageServer.js`.
- **Recommended Next Action:** Implement "Paired Desktop Mode" in Android app settings, permitting users to enter host IP/port or scan a QR code generated by the desktop app.

### GAP-02: Exact SQLite Trajectory & Step Schema Persistence
- **Feature:** Per-Conversation SQLite Database Persistence.
- **Original Location:** Local filesystem: `~/.gemini/antigravity/conversations/<conversation_id>.db`.
- **Required Services/RPCs:** `GetCascadeTrajectory`, `ListCascadeTrajectories`, `DeleteCascadeTrajectory`, `ArchiveCascadeTrajectory`.
- **Current Android Status:** In-Memory / Transient. P1.2 stores steps in temporary Kotlin memory structures; all history is lost on app restart.
- **Missing Functionality:**
  1. `conversations/<id>.db` SQLite file creation with exact table schemas (`steps`, `trajectory_meta`, `trajectory_metadata_blob`, `gen_metadata`, `executor_metadata`, `parent_references`, `battle_mode_infos`).
  2. Index creation on `steps(status)` and `steps(step_type)`.
  3. Protobuf binary blob serialization/deserialization for `steps.step_payload`, `steps.metadata`, and `trajectory_metadata_blob.data`.
- **Dependencies:** Android SQLite API (`SQLiteDatabase` / Room), Protobuf Java runtime.
- **Priority:** **P0 (Critical)** — Without this, conversation history cannot persist across reboots and desktop conversations cannot be imported.
- **Evidence:** Schema extracted from `c367db09-5d84-4822-8946-5d626af85692.db` and `b213d7c0-9bb6-4229-99be-7b7855c5c195.db`.
- **Recommended Next Action:** Create `TrajectorySqliteDatabaseHelper.kt` in `:core:database` matching desktop DDL exactly.

### GAP-03: Conversation Summaries & Full-Text Search (FTS5)
- **Feature:** Global Conversation Index & Multi-Step FTS5 Search.
- **Original Location:** `~/.gemini/antigravity/conversation_summaries.db`.
- **Required Services/RPCs:** `GetConversationSummaries`, `SearchConversations`, `DeleteConversationSummary`.
- **Current Android Status:** Mocked. Returns empty list or static placeholder.
- **Missing Functionality:**
  1. Persistent SQLite database `conversation_summaries.db`.
  2. Table `conversation_summaries` tracking `step_count`, `last_modified_time`, `workspace_uris`, `status`, `preview`, `agent_name`.
  3. Virtual table `conversations_fts` using `fts5` with `unicode61 remove_diacritics 2` tokenizer.
  4. Automatic FTS indexing of `user_body` and `agent_body` chunks upon message completion.
- **Dependencies:** Android SQLite with FTS5 support (standard in Android 9+ / API 28+).
- **Priority:** **P1 (High)** — Required for conversation drawer listing, search bar, and conversation switching.
- **Evidence:** Table DDL extracted from `conversation_summaries.db`.
- **Recommended Next Action:** Implement `ConversationSummariesRepository.kt` managing `conversation_summaries.db`.

### GAP-05: Model Configuration, Dynamic Catalog & Model Tiers
- **Feature:** Cascade Model Selection & Configuration.
- **Original Location:** `language_server.exe` (`GetCascadeModelConfigs`, `GetCascadeModelConfigData`, `GetAvailableModels`).
- **Required Services/RPCs:** `GetCascadeModelConfigs`, `GetCascadeModelConfigData`, `GetAvailableModels`, `GetCommandModelConfigs`.
- **Current Android Status:** Partially Implemented / Hardcoded. Returns minimal stub; agent engine is hardcoded to single Gemini model string.
- **Missing Functionality:**
  1. Complete protobuf response for `GetCascadeModelConfigsResponse` containing `client_model_configs` with model tiers:
     - `MODEL_TIER_FLASH_LITE` (sir_flash_lite, quick edits)
     - `MODEL_TIER_FLASH` (standard generation)
     - `MODEL_TIER_PRO` (complex planning, boost mode)
  2. Dynamic model switching based on user selection in Jetski UI model dropdown.
  3. Thinking config support (`thinkingConfig: { thinkingLevel: "LOW" | "HIGH" }`).
  4. BYOK (Bring-Your-Own-Key) model provider integration (Claude, OpenAI, Gemini).
- **Dependencies:** `GeminiModelProvider.kt`, protobuf schema definitions.
- **Priority:** **P0 (Critical)** — The user must be able to select models through the original UI dropdown rather than hardcoded backend constants.
- **Evidence:** Model enum inspection in `language_server.exe`; frontend selector logic in `main.js:1925500..1927600`.
- **Recommended Next Action:** Wire `GetCascadeModelConfigs` to return valid model metadata and update `AgentRuntime` to respect the selected model enum.

### GAP-06: Google Account OAuth Lifecycle & Secure Storage
- **Feature:** User Authentication & Token Refresh.
- **Original Location:** `language_server.exe` OAuth flow, deep link `antigravity://auth`, Google Gaia authentication.
- **Required Services/RPCs:** `GetUserStatus`, `GetAuthMode`, `AuthenticateWithCode`, `SetOAuthToken`, `RefreshOAuthToken`, `LogOut`.
- **Current Android Status:** Stubbed / Mocked. Returns static user info with `dev.agentic.local_readiness` flag; Gemini API key handled via plaintext.
- **Missing Functionality:**
  1. Integration with Google Sign-In or AppAuth-Android for mobile OAuth flow.
  2. Secure storage of refresh tokens using `AndroidKeyStore` (`EncryptedSharedPreferences`).
  3. Token refresh loop providing fresh access tokens to upstream requests.
  4. Separate handling for Google Account auth vs Gemini API Key auth.
- **Dependencies:** `androidx.security:security-crypto`, Android Chrome Custom Tabs.
- **Priority:** **P0 (Critical)** — Essential for authenticating against Google Cloud Code or Vertex AI services.
- **Evidence:** `dist/main.js` deep link handler; `language_server.log` Bearer token authentication.
- **Recommended Next Action:** Implement `AndroidOAuthManager.kt` using Chrome Custom Tabs and Android Keystore.

- **Required Services/RPCs:** `RunCommand`, `RunStreamingCommand`, `SendInputToCommand`, `KillCommand`.

- **Dependencies:** Android native process execution, coroutine streaming channels.
- **Priority:** **P1 (High)** — Necessary for executing build commands and terminal scripts.
- **Evidence:** `LocalCommandExecutionTool.kt`, `RunCommandOutput` protobuf definition.
- **Recommended Next Action:** Enhance `LocalCommandExecutionTool` with asynchronous piped stdout streaming.

### GAP-12: Real-Time gRPC-Web Streaming Transport Pipeline
- **Feature:** Unbuffered Token & Thought Streaming to UI.
- **Original Location:** HTTP/2 streaming response over loopback TLS.
- **Required Services/RPCs:** `SendUserCascadeMessage` response stream.
- **Current Android Status:** Partially Implemented. P1.2 uses buffered or pseudo-streaming via `WebResourceResponse`.
- **Missing Functionality:**
  1. True streaming pipeline using `PipedInputStream` / `PipedOutputStream` fed by coroutines.
  2. Proper gRPC-Web framing (`0x00` byte + 4-byte big-endian length prefix for data frames; `0x80` byte for trailer frames).
  3. Trailer frame containing `grpc-status: 0` and `grpc-message: OK`.
- **Dependencies:** Kotlin Coroutines `Channel`, OkHttp streaming, Android `WebResourceResponse`.
- **Priority:** **P0 (Critical)** — Crucial for smooth typing animations, real-time thought circulation, and progress feedback.
- **Evidence:** Binary framing specifications in gRPC-Web protocol; `LanguageServerGrpcWebHandler.kt`.
- **Recommended Next Action:** Refactor `SendUserCascadeMessage` response generation to use an unbuffered `PipedInputStream`.
