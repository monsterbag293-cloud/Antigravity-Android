## 3. Physical Android Device Qualification Specification

When a physical Android device is connected to the workstation, the following test protocol must be executed via ADB to qualify the hardware for native `language_server` execution:

### 3.1 Device Inspection Commands

```bash
# 1. CPU Architecture & ABI
adb shell getprop ro.product.cpu.abi
# Required output: arm64-v8a

# 2. Android OS Version & API Level
adb shell getprop ro.build.version.release
adb shell getprop ro.build.version.sdk
# Target: Android 12+ (API 31, 32, 33, 34, 35)

# 3. Kernel Version & Build
adb shell uname -r
adb shell uname -m
# Target: Linux kernel 5.10+, 5.15+, 6.1+, aarch64

# 4. Kernel Virtual Address Space Configuration
adb shell "zcat /proc/config.gz 2>/dev/null | grep -E 'CONFIG_ARM64_VA_BITS|CONFIG_PGTABLE_LEVELS'"
# Qualified Target: CONFIG_ARM64_VA_BITS_48=y, CONFIG_PGTABLE_LEVELS=4
# Fallback Warning: If CONFIG_ARM64_VA_BITS_39=y, TCMalloc will abort at startup.

# 5. Memory Capacity (RAM)
adb shell cat /proc/meminfo | grep -E 'MemTotal|MemAvailable'
# Minimum: 4 GB Total RAM (MemTotal >= 4000000 kB)
# Recommended: 6 GB – 8 GB Total RAM (to prevent LMK eviction during long agent turns)

# 6. Internal Storage Capacity
adb shell df -h /data
# Minimum Free Storage: >= 1.5 GB free on /data
```

## 4. Application Process & Tracing Context

When the application runs the PRoot subsystem on the device:
1. **Target SDK**: The Antigravity Android app targets `targetSdk = 34` (Android 14).
2. **SELinux Domain**: The app runs under `u:r:untrusted_app:s0:c...`.
3. **`ptrace` Permission Verification**:
   - Android's SELinux policy permits `ptrace` between processes with the exact same Linux UID (`u0_a...`).
   - Because PRoot and the guest `language_server` process are both spawned by the application's process tree, `ptrace` system call interception is fully permitted by the kernel without requiring root.
