# Phase P3.6.2: Minimal PRoot Environment Specification & Setup

## 1. Executive Summary

This report establishes the design, filesystem layout, security model, and packaging architecture for the **Minimal PRoot Debian ARM64 Userspace** designed to host Google's `language_server-linux-arm64` binary on Android.

The architecture eliminates all unnecessary Linux desktop packages, restricting the environment to the exact shared libraries and paths verified in Phase P3.6.1.

---

## 3. Trusted Base Rootfs Sourcing & Verification

In strict compliance with project security rules:
- **Source**: Official Debian 12 (Bookworm) ARM64 minimal base rootfs (`minbase`), published by the Debian Cloud Team / Docker Official Images.
- **Archive Size**: ~32 MB compressed (`rootfs.tar.xz`), uncompressing to ~85 MB.
- **Package Stripping**: All documentation, man pages, locales, development headers, package managers (`dpkg`, `apt`), and GUI libraries are stripped.
- **Integrity Verification**: The archive's SHA-256 hash is hardcoded into the Android asset verification table and validated before extraction.

---

## 4. PRoot Native Binary Compilation & Integration

### 4.1 Native Binary Packaging
- **Source**: Upstream PRoot (`termux/proot` / `corbinlc/proot` v5.3.0).
- **Target ABI**: `arm64-v8a` (Android NDK r26b / clang 17).
- **Packaging Format**: Packaged as a native shared library:
  `jniLibs/arm64-v8a/libproot.so`
- **Installation Path**: Extracted by Android's package manager into the application's read-only native library path:
  `/data/app/<package>/lib/arm64/libproot.so`
  This path is guaranteed to have `rx` (read and execute) permissions under Android's security architecture.

### 4.2 Syscall Redirection Parameters
PRoot is invoked from Java/Kotlin via JNI `execve()` with the following configuration:
```bash
/data/app/dev.agentic.antigravity/lib/arm64/libproot.so \
  -r /data/data/dev.agentic.antigravity/files/rootfs \
  -b /dev \
  -b /proc \
  -b /sys \
  -b /data/data/dev.agentic.antigravity/files/workspace:/workspace \
  -w /workspace \
  /usr/bin/language_server \
  --standalone=true \
  --persistent_mode=true \
  --http_server_port=57734 \
  --csrf_token=[REDACTED] \
  --gemini_dir=/home/user/.gemini
```

## 5. Security Architecture Compliance

| Security Dimension | Requirement | PRoot Implementation Status |
|---|---|---|
| **Root Permissions** | Zero root access allowed | **COMPLIANT**: PRoot uses `ptrace(2)`, not `chroot(2)`; requires zero root capabilities (`CAP_SYS_CHROOT`). |
| **SELinux Policy** | No SELinux modifications or permissive mode | **COMPLIANT**: Untrusted app domains permit `ptrace` between processes with identical UIDs. |
| **Filesystem Isolation** | No writes outside app sandbox | **COMPLIANT**: Rootfs and workspace reside entirely within `/data/data/<package>/files/`. |
| **Device Integrity** | No modifications to `/system` or `/vendor` | **COMPLIANT**: Zero modifications to host Android OS. |
| **Play Store Policy** | Compliance with Google Play developer policies | **COMPLIANT**: Standard user-space virtualization (matches UserLAnd on Google Play). |
