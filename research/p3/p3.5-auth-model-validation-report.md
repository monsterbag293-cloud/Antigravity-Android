## 4. Requirement 1 Compliance: Authentication Separation

To prevent confusion and maintain security integrity, Phase P3 enforces strict separation between the desktop Google session and local Android configurations:

### Architectural Boundaries
1. **No Fabricated Google Tokens**: The Android app does **not** generate fake Google OAuth tokens, mock login cookies, or synthetic Cloud Code credentials.
2. **Local Session Readiness**: The Android `AntigravityHostBridge` communicates its readiness as `Ready (Android Host Session)`, distinctly separated from the desktop Google profile.
3. **Independent BYOK Gemini API Key**:
   - The user-supplied Gemini API key (`AIzaSy...`) is used **only** when `BackendMode.LOCAL_GEMINI_FALLBACK` is explicitly selected.
   - The BYOK key is never forwarded to `language_server.exe`.
   - The BYOK key grants access solely to the public Gemini API (`generativelanguage.googleapis.com`) and does not confer Google Cloud Code or Antigravity Pro entitlements.
4. **Transparent User Interface**: The Settings screen displays the Desktop Hub status (with user name, email, plan tier, credits, and model count) separately from the BYOK API key input field.
