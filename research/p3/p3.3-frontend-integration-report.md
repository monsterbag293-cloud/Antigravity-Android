# Phase P3.3: Original Frontend Integration Report

## 1. Overview & Objective

Phase P3.3 integrates the original Antigravity Jetski Web React 19 frontend (running inside Android WebView) with the Paired Desktop Hub backend.

The primary challenges addressed in this phase are:
1. Intercepting gRPC-Web and Connect-RPC calls issued by the React application without breaking frontend state or event listeners.
2. Preserving binary frame integrity across the Android WebView boundary (`encoding = null`).
3. Providing an intuitive settings interface that enables seamless switching between `ORIGINAL_DESKTOP_HUB` and `LOCAL_GEMINI_FALLBACK`, displaying live connection status and Google account metadata.

---

## 2. Request Interception Pipeline

The interception architecture is implemented in `JetskiWebViewRequestInterceptor.kt`:

```mermaid
flowchart TD
    subgraph WebViewClient["Android WebView Client"]
        ShouldIntercept["shouldInterceptRequest(view, request)"]
    end

    subgraph URLCheck{"Is LanguageServerService RPC?"}
        ShouldIntercept --> URLCheck
    end

    subgraph StaticAssets["Serve Bundled Static Asset"]
        URLCheck -- No --> Assets["JetskiBundleLoader.openAsset()"]
    end

    subgraph RPCPipeline["gRPC-Web Relay Pipeline"]
        URLCheck -- Yes --> ExtractBody["Extract Request Payload\n(Stream or JS Base64 Bridge)"]
        ExtractBody --> DispatchHandler["LanguageServerGrpcWebHandler.handleRequest()"]
        DispatchHandler --> ModeSwitch{"BackendMode"}
        ModeSwitch -- ORIGINAL_DESKTOP_HUB --> Relay["RemoteHubProxyHandler.relayRequest()"]
        ModeSwitch -- LOCAL_GEMINI_FALLBACK --> LocalHandler["Handle with Local AgentRuntime"]
        Relay --> FormatResponse["Build WebResourceResponse\n- mimeType: application/grpc-web+proto\n- encoding: null\n- CORS Headers Added"]
        LocalHandler --> FormatResponse
    end

    FormatResponse --> DeliverToReact["Return WebResourceResponse to WebView Engine"]
```

### Key Technical Safeguards
- **Binary Frame Integrity**: Android's `WebResourceResponse` requires three parameters: `mimeType`, `encoding`, and `data` (`InputStream`). If `encoding` is supplied (e.g. `"utf-8"`), WebView attempts character transcoding, corrupting the binary gRPC-Web header (`0x00` and `0x80`). By strictly passing `encoding = null`, exact raw bytes are streamed to the React application.
- **CORS Negotiation**: The interceptor injects CORS response headers:
  - `Access-Control-Allow-Origin: *`
  - `Access-Control-Allow-Methods: POST, GET, OPTIONS`
  - `Access-Control-Allow-Headers: Content-Type, X-Grpc-Web, X-User-Agent, X-Codeium-Csrf-Token`
  - `Access-Control-Expose-Headers: grpc-status, grpc-message, x-grpc-web`

## 3. Settings UI: Dual Architecture & Mode Selection

The user interface in `SettingsScreen.kt` has been updated with a dedicated **Backend Execution Architecture (Phase P3)** control card:

### User Controls
1. **Mode Radio Selector**:
   - `ORIGINAL_DESKTOP_HUB` (Primary Mode): Routes all frontend requests to the desktop `language_server.exe` instance.
   - `LOCAL_GEMINI_FALLBACK` (Isolated Fallback): Routes all requests to the in-process Android Kotlin `AgentRuntime` using a BYOK Gemini API key.
2. **Hub Connection Parameters**:
   - **Host**: IP address or hostname of the desktop workstation (defaults to `127.0.0.1` for loopback or USB adb reverse, or LAN IP for Wi-Fi).
   - **Port**: Desktop daemon port (default `57734` for HTTP, `57733` for HTTPS).
   - **TLS Switch**: Enables secure TLS connection with loopback self-signed trust and remote certificate pinning.
   - **CSRF Token**: Authenticates requests against the daemon's `X-Codeium-Csrf-Token` requirement.
3. **Live Status Display**:
   - **Status Badge**: Displays `CONNECTED` (green), `CONNECTING` (yellow), `DISCONNECTED` (grey), or `ERROR` (red).
   - **Account Details**: When connected, displays genuine Google identity:
     - User Name: `Bean Bag`
     - User Email: `monsterbag293@gmail.com`
     - Plan Tier: `Pro (TEAMS_TIER_PRO)`
     - Prompt Credits: `500 Available`
     - Available Desktop Models: `14 models registered`
4. **Authentication Separation Notice (Requirement 1)**:
   - The BYOK Gemini API key card includes an explicit disclaimer:
     > *"This key is strictly used for LOCAL_GEMINI_FALLBACK mode. It does not confer Google Cloud Code or Antigravity Pro entitlements and is completely independent of Desktop Hub authentication."*
