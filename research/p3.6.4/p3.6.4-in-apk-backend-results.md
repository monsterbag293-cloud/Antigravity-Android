# Phase P3.6.4: Original Backend Execution Inside Android APK — Empirical Results

## 1. Executive Summary

This report documents the empirical proof that **Google's original, unmodified AArch64 language server binary (`language_server-linux-arm64`) can be launched and operated directly inside an unprivileged Android application sandbox** on a physical retail **Google Pixel 10 Pro (`blazer`)** running **Android 17 (API 37)** with Linux kernel **6.6.127**.

The execution occurred within an isolated diagnostic APK (`dev.agentic.proot.diag`) running under its own private UID (`10383` / `u0_a383`) and the standard `untrusted_app_34` SELinux domain, without root privileges, without SELinux modifications, and without bypassing Android security controls.

The backend successfully:
1. Initialized TCMalloc on the physical device's 39-bit virtual-address kernel.
2. Spanned its internal goroutines, listening on loopback ports `58888` (HTTP) and `37573` (HTTPS gRPC).
3. Generated its official Hub discovery file (`hub_58888.json`) in **510 ms**.
4. Served the original Google Antigravity single-page application frontend bundle (`<title>Antigravity</title>`) over loopback HTTP.
5. Responded with HTTP 200 to Connect-RPC calls (`GetStatus` and `GetUserStatus`), correctly reporting unauthenticated status and Cascade model configuration data structures.
6. Maintained operational integrity through Android activity backgrounding (`KEYCODE_HOME`) and foreground resumption.
7. Terminated cleanly on request and left zero orphaned or zombie processes upon application force-stop.

### 2.3 Linker Compatibility Patch Analysis
Android's Package Manager extracts only `.so` files from `jniLibs` and ignores `.so.2` files. Because upstream `proot` links against `libtalloc.so.2`, the binary was patched in its `.dynstr` section:
- **Target String**: `libtalloc.so.2\x00` (15 bytes)
- **Replacement String**: `libtalloc.so\x00\x00\x00` (15 bytes)
- **Integrity**: Exactly preserves table offsets, section headers, and byte boundaries while enabling Android's Bionic dynamic linker to load `libtalloc.so` directly from `nativeLibraryDir`.

## 4. Stage 3: In-App Startup & Architecture

### 4.1 Invocation from Android Kotlin Process
The language server was spawned from Kotlin using `ProcessBuilder` inside `ProotDiagnosticActivity`:

```kotlin
val backendCmd = listOf(
    prootFile.absolutePath,
    "-r", rootfsDir.absolutePath,
    "-b", "/proc",
    "-b", "/dev",
    "-b", "/sys",
    "/usr/bin/language_server",
    "--standalone=true",
    "--persistent_mode=false",
    "--http_server_port=58888",
    "--csrf_token=$csrfToken",
    "--gemini_dir=/tmp/gemini_sandbox",
    "--app_data_dir=antigravity-test",
    "--disable_telemetry=true",
    "--headless=false",
    "--override_ide_name=antigravity",
    "--subclient_type=hub"
)

val pb = ProcessBuilder(backendCmd)
pb.environment().putAll(
    mapOf(
        "HOME" to "/root",
        "USER" to "root",
        "PATH" to "/usr/bin:/bin",
        "LD_LIBRARY_PATH" to nativeLibDir,
        "PROOT_LOADER" to loaderFile.absolutePath,
        "PROOT_TMP_DIR" to tmpDir.absolutePath
    )
)
val proc = pb.start()
proc.outputStream.close() // Close stdin to signal non-interactive CLI EOF
```

### 4.2 Key Architectural Discoveries
1. **The `$HOME` Environment Requirement**:
   Google's Go runtime and token storage initialization (`auth_client.go:177`) invokes `os.UserHomeDir()`. Because Android's Bionic process launcher does not set `HOME` by default, launching without `HOME` triggered a nil-pointer dereference in `GetAuthStatus`. Supplying `"HOME" to "/root"` resolved this cleanly.
2. **Headless vs Server Flags**:
   Passing `--headless=true` commands the language server to execute an interactive console OAuth flow that blocks reading authorization tokens from stdin (`Enter the authorization code:`). Passing `--headless=false` (matching Google's desktop UI launch) enables daemon operation, generating `hub_58888.json` immediately and delegating authentication to Web/RPC clients.
3. **Hub Discovery File Path**:
   Google's backend writes the discovery file to `<gemini_dir>/<app_data_dir>/daemon/hub_<PORT>.json` (specifically `/tmp/gemini_sandbox/antigravity-test/daemon/hub_58888.json`), not in the root of `gemini_dir`.

## 6. Stage 5: Android Lifecycle & Process Control

### 6.1 Backgrounding & Foreground Resumption
1. **Activity Backgrounding**:
   - Dispatched `input keyevent KEYCODE_HOME`.
   - Inspected `ps -AZ`: PID `20169` (`dev.agentic.proot.diag`), PID `20231` (`libproot.so`), and PID `20236` (`language_server`) all remained resident in memory in sleep state `S`.
   - No signal deaths, OOM kills, or ANRs occurred.
2. **Activity Foreground Resumption**:
   - Re-launched `am start -n dev.agentic.proot.diag/.ProotDiagnosticActivity`.
   - The activity resumed smoothly; the backend process remained alive and responsive.

### 6.2 Controlled Shutdown & Force-Stop Audit
1. **Controlled Shutdown**:
   - The diagnostic activity invoked `proc.destroy()`.
   - PRoot propagated termination to child processes; the backend exited cleanly with exit code `255`.
   - Inspection of `ps -AZ` confirmed neither `language_server` nor `libproot.so` remained running.
2. **Application Force-Stop**:
   - Dispatched `am force-stop dev.agentic.proot.diag`.
   - Inspected `ps -AZ | grep dev.agentic.proot`.
   - **Result**: Zero lingering, orphaned, or zombie processes.

## 8. Final Verdict

In accordance with strict project rules, the final verdict explicitly distinguishes between the individual capabilities:

1. **PRoot inside APK**: **PASS**
   - Packaged as `libproot.so` via `jniLibs`, extracted with execute permissions, intercepted syscalls with zero SELinux denials.
2. **Original Backend inside APK**: **PASS**
   - Google's unmodified `language_server-linux-arm64` binary launched inside the Debian rootfs under PRoot, spawned threads, initialized TCMalloc, and operated under Android application UID `10383`.
3. **Local Hub / RPC Functionality**: **PASS**
   - Generated valid Hub discovery file (`hub_58888.json`), served the genuine Antigravity single-page app HTML on `http://127.0.0.1:58888/`, and responded to Connect-RPC `GetStatus` and `GetUserStatus` calls with HTTP 200.
4. **Genuine Cascade Functionality**: **NOT TESTED / BLOCKED ON AUTHENTICATION**
   - The backend was intentionally run in unauthenticated mode without logging into a Google account or connecting to external inference endpoints, complying strictly with project rules. As reported by `GetUserStatus`: `You are not logged into Antigravity`. Full agent turns require subsequent Phase P3.7 integration with Google OAuth and inference credentials.
